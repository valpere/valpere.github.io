## Огляд

Давати AI-агентам прямі паролі від бази даних або адмін-токени CRM — це гарантований інцидент безпеки: один неточний запит або промпт-інʼєкція може вивантажити персональні дані клієнтів, перезаписати продакшн-записи або влаштувати шквал API-запитів. Кастомний **MCP-шлюз (Model Context Protocol)** стає між вашими AI-агентами (Claude, Cursor, OpenCode, Cline чи власними ботами) і корпоративними системами (PostgreSQL, KeyCRM, SalesDrive, Google Workspace, Notion, ERP) — відкриваючи лише типізовані інструменти з рольовим доступом (RBAC), розділенням read/write, валідацією параметрів і незмінним аудит-логом.

**Результат: будь-який MCP-сумісний агент безпечно працює з живими даними компанії, секрети й ключі залишаються запечатаними на сервері, а кожен виклик перевіряється і логується.**

---

## Справжня складна задача

Підключити агента до внутрішнього API для демо — справа кількох годин; зробити це безпечним для щоденної роботи бізнесу — справжній виклик. Мовні моделі не гарантують дотримання «мʼяких» заборон у промпті на кшталт «нічого не видаляй» або «дивись лише цього клієнта». Безпека має жити в детермінованому коді сервера: параметризовані запити, білі списки інструментів по ролях, маскування чутливих полів у відповідях, ліміти частоти та обовʼязкове підтвердження для запису.

---

## Як це працює

1. **Стандартизований MCP-транспорт.** Шлюз надає єдиний MCP-сервер (`stdio` для локальних dev-агентів або захищений Streamable HTTP / SSE через TLS для віддалених команд і бекенд-ботів).
2. **RBAC і білий список інструментів.** Кожен токен агента чи користувача привʼязаний до політики прав (наприклад, `analyst` має лише read-only представлення БД/CRM; `ops-agent` може створювати чернетки тікетів; видалення та масові експорти заблоковані).
3. **Детерміновані guardrails і валідація схем.** Кожен виклик перевіряється за суворою JSON-схемою, SQL виконується лише параметризовано на read-replica з лімітом рядків і таймаутом, а секрети (паролі, токени, номери карток) маскуються до потрапляння в контекст LLM.
4. **Повний аудит-лог.** Кожен виклик фіксує `(actor, tool, arguments_hash, latency_ms, status, rows_returned)` у PostgreSQL, даючи команді безпеки й інженерам прозору картину дій агентів.

## Ключові рішення

| Рішення | Чому |
|---|---|
| Секрети й ключі живуть виключно всередині MCP-сервера | Агенти ніколи не бачать паролів БД, API-ключів CRM чи OAuth-токенів — відкликання або ротація доступів робиться в одному місці за секунди. |
| Розділення read-only та write інструментів через RBAC | Унеможливлює ескалацію прав через промпт-інʼєкцію: агент-аналітик фізично не може змінити замовлення, ціни чи права користувачів. |
| Параметризовані інструменти замість сирого SQL/HTTP | Повністю закриває SQL-інʼєкції, важкі повні скани таблиць (діють `LIMIT` і statement timeout) та довільні SSRF-запити. |
| Маскування PII на виході та аудит-лог | Не допускає витоку чутливих полів у логи сторонніх LLM-провайдерів і формує повну історію кожної дії агента. |

## Що ви отримуєте

- Кастомний продакшн MCP-сервер (Go або Python/TypeScript) під ваші бази даних, CRM, Google Sheets/Drive, Notion або внутрішні REST API
- Політики рольового доступу (`read-only`, `draft-write`, `approval-required`), rate limiting і правила маскування PII
- Docker-розгортання з TLS-авторизацією та готові конфіги підключення для Claude Code/Desktop, Cursor, OpenCode або власного AI-бекенду
- Схему аудит-логу, набір автотестів і документацію для розширення новими інструментами

---

## Межі

- MCP-сервер забезпечує контроль доступу на рівні інструментів і схем, але не замінює мережеві фаєрволи та регулярні бекапи БД.
- Цільові корпоративні системи повинні мати API, вебхуки або підключення до read-replica бази даних.
