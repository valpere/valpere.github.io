## Огляд

Сучасні спам-скрипти й AI-агенти легко обходять класичну CAPTCHA та заливають форми заявок на сайтах, публічні API і Telegram-чати фейковими лідами, сміттєвими реєстраціями й накрутками. Жорстке блокування всіх підряд ріже конверсію живих клієнтів, а відкриті форми завалюють пошту й CRM сміттям. **Трирівневий антибот і антиспам шлюз** поєднує edge-захист (Cloudflare Turnstile, WAF, rate limiting), детерміновану поведінкову перевірку та легкий когнітивний гейт (Cognitive Proof-of-Work) виключно для підозрілих запитів.

**Результат: автоматизований бот-трафік і AI-спам у формах падають на 95%+, живі користувачі проходять без тертя за мілісекунди, а CRM, пошта й Telegram залишаються чистими.**

---

## Справжня складна задача

Класичні графічні капчі дратують реальних покупців зі смартфонів, тоді як дешеві сервіси розгадування та headless-браузери проходять їх автоматично. Прості чорні списки IP не працюють через мобільний CGNAT і резидентні проксі. Надійний захист будується пошарово: дешеві детерміновані фільтри на периметрі, серверні поведінкові сигнали (швидкість заповнення, honeypot, перевірка тимчасових email-доменів і дублів) та ескалація лише «сірого» трафіку на коротке когнітивне питання, яке ламає stateless-ботів.

---

## Як це працює

1. **Рівень 1 — Периметр і протокол.** Правила Cloudflare WAF, невидимий Turnstile, ковзні ліміти частоти в Redis по IP/підмережах та скоринг ASN відсікають масові бот-хвилі ще до бекенду.
2. **Рівень 2 — Детермінований поведінковий гейт.** Серверний middleware перевіряє швидкість заповнення форми (менше 1 секунди), приховані поля-пастки (honeypot), одноразові поштові домени, повтори хешів тексту та евристики профілю з нульовою витратою на LLM.
3. **Рівень 3 — Адаптивний Cognitive Gate (лише для підозрілого трафіку).** Запити із «сірої зони» (або нові учасники Telegram-груп / публічних тікет-форм) отримують одне коротке контекстне питання з обмеженим часом — елементарне для живої людини, але непрохідне для масових скриптів.
4. **Карантин і телеметрія.** Заблоковані запити фіксуються з кодом причини (`waf_rate`, `honeypot`, `turnstile_fail`, `cognitive_timeout`) у таблиці карантину, щоб можна було перевірити спірні кейси без втрати реальних клієнтів.

## Ключові рішення

| Рішення | Чому |
|---|---|
| Невидимий Cloudflare Turnstile замість графічних капч | Реальні відвідувачі проходять автоматично без кліків по світлофорах — конверсія на мобільних не падає. |
| Три ескалаційні рівні (Edge → Детермінований → Когнітивний) | Відсікає 90% сміття практично за нульову ціну ще до залучення LLM або уваги модератора. |
| Черга карантину замість «тихого» видалення | Дозволяє власнику сайту перевіряти прикордонні випадки й підлаштовувати правила без ризику мовчки загубити клієнта. |
| Єдиний рушій для Web/API і Telegram-спільнот | Та сама звʼязка Redis rate-limit + поведінковий скоринг + когнітивна перевірка захищає форми WordPress/OpenCart/сайтів і Telegram-чати. |

---

## Що ви отримуєте

- Налаштований Cloudflare WAF + Turnstile + Nginx/Redis rate-limiting для вашого сайту та API
- Серверний антиспам-middleware (Go / Python / PHP) із honeypot, дедуплікацією та журналом карантину
- Опційно — антиспам-бота для Telegram-груп і каналів із когнітивною перевіркою входу й автомутом спамерів
- Алерти при сплесках атак та інструкцію налаштування порогів спрацювання

---

## Межі

- Захищає прикладний рівень (вебформи, API, Telegram-вхід); мережевий L3/L4 DDoS закривається на рівні інфраструктури Cloudflare/хостингу.
- Потребує доступу до DNS/Cloudflare для edge-правил або доступу до сервера/бота для бекенд-middleware.
