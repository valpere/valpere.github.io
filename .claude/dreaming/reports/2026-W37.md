## 4. Recurring `/fix-review` themes
### a) "Diagram duplication as page hero" — 3+ PRs
- Confidence: medium (themes inferred from commit titles, since merged PR review comments aren't surfaced by `gh pr view --json comments` after merge)
- Evidence: PRs #108 (pad subgate diagram to minimum size), #121 (`fix(tumanomir): stop duplicating the command-flow diagram as the page hero`), #131 (`fix(portfolio): stop duplicating the diagram as page hero`), #132 (`fix(portfolio): stop duplicating diagrams as page hero (6 more entries)`).
- Pattern: A diagram gets included once in the page body, then the `_layouts/portfolio-item.html` (or similar) re-renders the same image as a hero. The fix is to skip the hero when the body's first image already is it (or to render a hero *and* an inline body copy with different crops).
- Suggest: Add a CLAUDE.md convention: "When a portfolio entry contains exactly one diagram, do not duplicate it as the page hero — render either the hero or the inline, not both. For multi-diagram entries, use the first diagram as hero only if it's distinct from the diagrams that follow." This avoids the recurring #131/#132 fixes.

### b) "i18n chrome localization" — 3+ PRs
- Confidence: medium
- Evidence: PRs #126 (`Localize breadcrumb + info-bar chrome on project/portfolio pages`), #127 (`Localize portfolio entry titles (client_uk) across cards, home, detail pages`), #133 (`Localize hero images: English hero on EN pages, Ukrainian on UK pages`).
- Pattern: New chrome strings get added without `*_uk` siblings; later passes localize them.
- Suggest: CLAUDE.md addition: "When adding any user-visible string to a template, partial, or card layout under `_includes/` or `_layouts/`, add the `_uk` translation in the same change. Don't ship the EN half and plan to localize later — the next dreaming pass will flag it, but the goal is zero `*_uk` drift by PR time." (Aligns with the existing bilingual content pattern already stated for `projects/`.)
